SECTION 1 — WHAT WE ARE BUILDING

This is a personal portfolio website for Fagbo Kehinde Omolola — a Nigerian product engineer, AI builder, technical writer, and product management learner, based in Ilorin, Nigeria.

The portfolio serves two visitor types: recruiters evaluating her for remote roles, and investors or collaborators interested in her startup Provly. The site has two AI-powered features: a chatbot that answers visitor questions about her work, and a **public** cover letter generator — a recruiter pastes their own job description and receives a letter written in Kehinde's voice, live, as an interactive demonstration of her AI-building ability. This is a deliberate change from an earlier draft that described this as a private tool — it is now explicitly a public-facing skill demo, since that's what actually serves a recruiter's evaluation, not just Kehinde's own convenience.

SECTION 2 — TECH STACK (LOCKED — DO NOT CHANGE)

Core Framework
▪ Next.js (App Router) — confirm current stable version before starting; do not assume "14" without checking
▪ TypeScript, strict mode
▪ Tailwind CSS alongside CSS variables

Database and ORM
▪ PostgreSQL via Supabase
▪ Prisma ORM — all database access goes through Prisma
▪ DATABASE_URL (pooled) and DIRECT_URL (migrations)

Authentication
▪ NextAuth.js v5 with Prisma adapter — admin authentication only
▪ Visitors never log in
▪ All four NextAuth Prisma tables required: User, Account, Session, VerificationToken

AI
▪ OpenAI official Node/TypeScript SDK — no raw HTTP calls
▪ gpt-4o-mini for chatbot — cost efficiency
▪ gpt-4o for cover letter generator — quality requirement
▪ API keys written by hand into .env — never generated by any agent

Infrastructure
▪ Vercel — deployment, hosting, CI/CD
▪ Vercel Blob — project screenshot storage
▪ Vercel KV — system prompt caching (300s TTL)
▪ Upstash Redis — rate limiting, persistent across serverless cold starts
▪ Resend — transactional email if needed

⛔ RULE: Never use in-memory counters for rate limiting — they reset on cold starts in serverless. Always Upstash Redis.
⛔ RULE: Never store files in the database. Screenshots go to Vercel Blob; only the storage key string is stored.
⛔ RULE: Never rebuild the system prompt on every chat message. Cache in Vercel KV, key portfolio:context, 300s TTL. Invalidate on any project/skill update.
⛔ RULE: Never hardcode a hex color value in a component. Always use CSS variables from design-tokens.css.

SECTION 7 — AI FEATURE SPECIFIC RULES

Chatbot Rules (unchanged): gpt-4o-mini only, streaming enabled, dynamic system prompt via context-builder.ts, never fabricate, responses under 150 words unless asked for more, rating slot per message, 10s timeout with fallback message.

Cover Letter Generator Rules — updated for public scope:
▪ Model: gpt-4o, non-negotiable for quality.
▪ **This feature is public-facing** — any visitor may use it, not only Kehinde. Treat it accordingly: rate limiting and abuse-resistance matter here exactly as much as on the chatbot.
▪ No streaming — wait for full response.
▪ Validate word count: target 250–350 words, retry once if outside range.
▪ System prompt must state explicitly: never fabricate skills or projects not listed below.
▪ Log every generation to CoverLetterGeneration — jobDescription truncated to 500 chars, no full job posting retained long-term.
▪ 15s timeout — longer than chatbot's, due to longer output.
▪ Because this is now public, add a small clarifying line near the feature itself: something like "See how Kehinde's AI-building skills work — paste a job description and get a cover letter written in her voice." This frames it correctly as a demo, not confusing UX.
